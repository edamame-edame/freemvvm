# Property notification host-boundary integration

- Updated: 2026-10-20
- Status: complete; implementation unit `UNIT-CORE-049`

## Goal

Connect the existing bounded Property-delivery slice to the outer host-event boundary. Deliver notifications after the active event/post callback returns, before another ordinary callback can run when work was generated by that callback, preserve the 128-complete-item slice, schedule a normal wake for remaining work, and let pending shutdown control work take precedence.

## Steps

1. Register `UNIT-CORE-049` and its focused host-boundary oracles before changing Rust sources.
2. Invoke one notification slice only after an outer host scope closes and only after pending shutdown has been serviced.
3. Stop after a complete delivery item if a notification callback requests shutdown; service shutdown before any remaining item.
4. Schedule a normal host wake when a slice leaves notification work, without replacing an already-pending normal wake or a priority shutdown wake.
5. Run focused notification/dispatcher tests, the workspace suite, the repository development gate, documentation/link checks, and `git diff --check`; update memory and commit/push this unit.

## Scope boundary

This unit integrates the existing queue and delivery item at outer host-event and dispatcher-post boundaries. It does not yet wrap public C ABI Property setters in host-event scopes. Binding propagation, exception diagnostics, external UI-event adapter wiring, public Property API boundaries, and shutdown-time destruction of pending Subscription work remain separate work.
