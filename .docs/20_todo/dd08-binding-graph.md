## 作業項目

1. ADR-0001、要件、基本設計のBinding意味論と通知診断境界、DD-01～07の承認済み責務を照合する。
2. 初期同期、TwoWay同期グループ、OneWay DAG、競合優先順位、解除・保留更新の処理境界を判断ID付きの案にする。
3. Binding作成の検証順と失敗原子性、後続伝播時のValidation失敗、エラー状態・通知の規則をA13～A16およびDD-06/07と整合させる。
4. DD-PROP-09の通知slice（最大128完了item）とBD-03の因果連鎖停止を区別し、長期保留・非収束の診断と回復範囲を提案する。判定不能な一般callbackを必ず停止できるとはしない。
5. 上位判断だけでは決まらない事項を明示し、レビュー用の検証ケースと隣接文書への更新箇所を整理する。
6. DD-08の承認結果を同じ詳細設計文書へ反映し、`.docs/20_todo/detail-design-phases.md` と `.docs/01_memory/detail-design-planning-status.md` を更新する。
7. Markdown参照と差分を点検し、`git diff --check` を実行する。
