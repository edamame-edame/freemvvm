# 実装単位・unit-test・GitHub Actions対応計画

- 状態: レビュー案作成・検証完了
- 着手日: 2026-10-12
- 根拠: 利用者指示。実装とunit-testを同じ段階に置き、各実装単位のテスト設計・実行と変更ファイルのGitHub workflow検証を対応づける

## 作業範囲

1. 要求仕様の成果物関係図にunit-testをsoftwareと並列で追加し、参照矢印は下流から上流へ向ける。
2. 実装単位ごとに、対応するunit-test設計・テスト対象・実行結果・対象revisionを追跡する方針をレビュー案にする。実装単位をソースファイルと同義にしない。
3. 変更ファイルから実装単位と影響テストを特定する対応表の案を作る。unit-test対象の変更漏れ時に広いテストへフォールバックする条件も定義する。
4. GitHub Actionsの実行タイミングをpushおよびpull request更新として提案し、変更ファイルに対応するunit-testと影響回帰の起動、結果のcommit SHAへの紐付けを記述する。
5. unit-test、要求test、release/version testの役割と相互参照を整理する。
6. workflowやテスト実装が存在しない現状を確認し、レビュー案と将来の実装作業を区別する。言語別実行環境・job matrix・test frameworkは根拠なしに確定しない。
7. 相対リンク、参照方向、文書状態、`git diff --check`を確認する。

## 承認境界

実装とunit-testを対応づける方針、および変更ファイルをGitHub Actionsで検証する要求は利用者指示に基づく。unit ID形式、テストframework、workflow job、runner、変更からテストを選ぶ実装方式はレビュー案として提示し、利用者確認前に確定しない。実ファイルやCI workflowの作成は、実装基盤と対応する設計が揃った後続作業とする。
