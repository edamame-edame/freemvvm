# 要求・設計文書の参照方向とセキュリティ設計追加計画

- 状態: 完了
- 着手日: 2026-10-12

## 作業範囲

1. 文書の生産・依存関係と、本文中の参照リンクの向きを区別して定義する。参照リンクは下流文書から上流の根拠文書へ向ける。
2. 要求仕様の総目次から要求テスト表・基本設計・詳細設計/API設計への下流リンクを除く。総目次からRQ章への章リンクは維持する。
3. 各RQ章から設計対応・要求test対応・traceability行の下流リンクを除く。RQ本文とIDを正本とし、要求テスト表および設計側が必要なRQを上流参照する。
4. 成果物関係図を参照方向で描き直し、basic-designの下にdetailed-design / api-design / secure-designを並列で置く。設計判断やセキュリティ要求自体は追加決定しない。
5. secure-design用の入口文書・初期計画を追加し、要求および基本設計を上位の参照元として示す。未着手・未承認の状態を明記する。
6. AGENTS.md、要求再編計画、要求再編状態メモを参照方向とsecure-designの構造に合わせて更新する。
7. Markdownリンクの存在、RQ章における下流リンクの不在、参照方向図の内容、`git diff --check`を確認する。

## 承認境界

参照方向とsecure-designの追加は利用者指示に基づく。既存RQ、BD、DDの意味・承認記録は変更しない。secure-designの本文は入口と計画に限り、セキュリティ要求・脅威モデル・対策を確定しない。
