## 移行の具体手順案

SEP-ID-01: 既存IDは「元文書＋ID＋対象文」で識別する。RQ08と旧IDを再利用せず、意味維持の整形では改番しない。分割が必要な場合だけその章の未使用番号を提案し、仮候補SEP-RQ-*から正式RQへの対応を承認記録に追記する。

SEP-ID-02: 一つの設計IDの外部保証をRQへ分けても、残る設計判断のIDを維持する。既存A番号の宣言をDD分冊へ移す場合は旧A→新文書/節の対応を残す。移管先の承認前に旧正本の意味を削除しない。

SEP-ID-03: RQ-15の複数意味はrq15-migration.mdに従い、同じ意味の既存RQへ統合するか新IDへ分割する。旧IDは廃止・統合の理由と同層のRQ正本を示し、履歴を失わない。新RQから旧BD/DD/testへ由来リンクを作らず、由来はこの補助台帳に置く。

SEP-ID-04: 承認履歴は「旧意味の承認」「分離案の承認」「要求本文の承認」「設計本文の承認」「適用日/版」を分ける。改訂履歴は今回の分割・移管・意味差と承認範囲を追記する。古いレビュー待ち行は日付付きの過去状態として保持し、現在のヘッダと矛盾させない。

SEP-ID-05: 文書参照は実際の上流定義へ向ける。RQ→RQ索引/章のナビゲーションは可、RQ→BD/DD/SD/testの根拠参照は作らない。BD→後続DD割当は計画へ移す。DD間は共通定義への依存と進行順を区別し、番号順を根拠にリンクを全削除しない。

## 移行検査と完了条件

適用対象行ごとに旧文・新文、正本、正式ID、意味差、承認範囲、case/assertion、影響pathと結果を記録する。全現行RQ IDを要求test表と突合し、旧IDの消失/二重定義、参照先不在、逆向き参照、status再利用、候補の採用誤記を検査する。

レビュー案が揃った状態を正本移行完了と記録しない。要求変更に依存する設計本文は要求採否後に適用する。未決が残る項目は担当成果物・候補・必要な選択を明記し、対応する実装/実行gateをblockedまたは対象stageとして記録する。
