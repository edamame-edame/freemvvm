## 設計本文の改訂案

pure-Python wrapper packageには公開API、ctypes宣言、型情報を収録する。native runtimeはtarget別distributionとして解決し、wrapper loaderがversion/ABI/feature適合を確認してからロードする。ARMはboard/libc/profile互換性が確認された形式で導入し、package labelと実際の互換性を照合する。

```mermaid
flowchart LR
    N0["wrapper install"]
    N1["native target解決"]
    N0 --> N1
    N2["identity/適合検証"]
    N1 --> N2
    N3["loader"]
    N2 --> N3
    N4["Core"]
    N3 --> N4
```

## 移管・ID・検証への影響

- 既存ID: BD-17。方式として残る意味は旧IDを維持し、要求へ分ける文だけを仮候補IDに対応付ける。正式RQ IDの発番は[移行案](id-migration.md)による。
- 移管先: 利用者可視条件は上記RQ候補、C/言語APIの具体形はDD内、脅威と防御はSD、試験操作と判定手順はrequirements-test/unit-test、着手順と下流割当はto-do。
- 設計を説明する所有・state・call図と計算例は保持する。対象本文の試験節は、[検証改訂案](test-impact.md)へ対応付けてから移す。失敗時の状態表・cleanup順まで検証扱いで削除しない。
- 上流RQ/ADR/BDへの参照は該当記述に直接置く。後続の着手割当は計画へ移し、DD間のinterface依存参照は実際の定義側へ向けて循環を解く。文書番号の大小だけで依存を判定しない。
