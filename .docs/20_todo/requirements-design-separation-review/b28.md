## 対象本文と既存承認

- 状態: BD-28承認済み（2026-09-27）

作成時点の原文SHA-256: `03e908531f1310b36951295698f574d7ff396c9972b1ad2140e435b402a44031`。対象は台帳の箇所と、以下の原文・判断ID。正本の本文は今回編集していない。

原文 本文項目1 / L16:

> 安定版native C ABI runtimeの公開versionは`MAJOR.MINOR.PATCH`の三要素で表す。 各native artifactとrelease metadataはこのversionを同じ意味で使う。

原文 本文項目2 / L17:

> `MAJOR`はA3のC ABI symbol suffixのmajorと一致させる。 異なるmajorのruntimeは異なるABI世代として扱う。破壊的変更を伴わないABI追加はMINOR、ABI互換性を変えないbug/security fixはPATCHを上げる。

原文 本文項目5 / L20:

> この判断の適用対象は安定版native runtimeの互換version規則に限定する。 初回stable release番号、pre-release identifier、build metadata、release cadenceはこの判断では固定せず、公開release運用を決める時点で別途定める。

## 設計本文の改訂案

Runtime version、ABI major、wrapper versionを独立metadataとして持ち、loaderはwrapperのrequired major/minimum minorとRuntimeの提供情報を照合する。同majorの互換追加は新symbol/featureへ割り当て、破壊変更は別majorのsymbol空間に置く。release metadataとqueryの値を同じversion情報から生成する。

```mermaid
flowchart LR
    N0["wrapper互換条件"]
    N1["runtime discovery"]
    N0 --> N1
    N2["major/minor/feature照合"]
    N1 --> N2
    N3["symbol解決"]
    N2 --> N3
    N4["呼出し"]
    N3 --> N4
```

## 移管・ID・検証への影響

- 既存ID: BD-28。方式として残る意味は旧IDを維持し、要求へ分ける文だけを仮候補IDに対応付ける。正式RQ IDの発番は[移行案](id-migration.md)による。
- 移管先: 利用者可視条件は上記RQ候補、C/言語APIの具体形はDD内、脅威と防御はSD、試験操作と判定手順はrequirements-test/unit-test、着手順と下流割当はto-do。
- 設計を説明する所有・state・call図と計算例は保持する。対象本文の試験節は、[検証改訂案](test-impact.md)へ対応付けてから移す。失敗時の状態表・cleanup順まで検証扱いで削除しない。
- 上流RQ/ADR/BDへの参照は該当記述に直接置く。後続の着手割当は計画へ移し、DD間のinterface依存参照は実際の定義側へ向けて循環を解く。文書番号の大小だけで依存を判定しない。
