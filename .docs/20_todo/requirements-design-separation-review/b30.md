## 対象本文と既存承認

- 状態: BD-30承認済み（2026-09-27）

作成時点の原文SHA-256: `6fd3e035b5c7f3383073fbde49837cd28ac710e7562a18e9e4d205a1b6bc5fb7`。対象は台帳の箇所と、以下の原文・判断ID。正本の本文は今回編集していない。

原文 本文項目1 / L16:

> native runtime artifactのcanonical release catalogを一つ設ける。 公式manifestとimmutable artifact identityの権威ある取得先はこのcatalogとする。各language wrapper registryで配る同一native binaryは同じmanifest identity/digestを参照し、独自に再ビルド・再ラベルしない。

原文 本文項目2 / L17:

> language wrapperは各言語の既定package managerで配布する。 Python wheel、NuGet、CMake package、Cargo crateはBD-17～BD-20の形を保つ。package managerが対象target向けnative assetを同梱・取得する場合も、BD-29の公式identity・manifest・digestと一致させる。

原文 本文項目4 / L19:

> 再現可能なbuildではruntime versionとdigestへ解決結果を固定する。 `latest`等の可変aliasをCI/正式release buildの入力として残さない。lock/manifest等に解決済みidentityを記録し、cacheはidentity＋digestをkeyにする。通常package installでの暗黙更新は行わず、wrapper dependency更新か明示的なruntime upgradeで更新する。

## 設計本文の改訂案

canonical catalogをartifact identityの取得元とし、language package assemblerは同じ検証済みnative bytesを取り込む。selectorはconsumer target/profileを入力として必要featureとABIを照合する。fetch/importは明示要求から起動し、既存cacheに同じidentityで異なるbytesを上書きしない。offlineでは検証済みbundleを同じselectorへ渡す。

```mermaid
flowchart LR
    N0["target/profile + pin"]
    N1["catalog/cache resolve"]
    N0 --> N1
    N2["適合/信頼検証"]
    N1 --> N2
    N3["language package/link/load"]
    N2 --> N3
```

## 移管・ID・検証への影響

- 既存ID: BD-30。方式として残る意味は旧IDを維持し、要求へ分ける文だけを仮候補IDに対応付ける。正式RQ IDの発番は[移行案](id-migration.md)による。
- 移管先: 利用者可視条件は上記RQ候補、C/言語APIの具体形はDD内、脅威と防御はSD、試験操作と判定手順はrequirements-test/unit-test、着手順と下流割当はto-do。
- 設計を説明する所有・state・call図と計算例は保持する。対象本文の試験節は、[検証改訂案](test-impact.md)へ対応付けてから移す。失敗時の状態表・cleanup順まで検証扱いで削除しない。
- 上流RQ/ADR/BDへの参照は該当記述に直接置く。後続の着手割当は計画へ移し、DD間のinterface依存参照は実際の定義側へ向けて循環を解く。文書番号の大小だけで依存を判定しない。
