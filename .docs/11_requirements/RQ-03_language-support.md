# RQ-03: 対応言語と共通意味論

- 文書版: 0.5
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

各対応言語から同じUI機能とMVVM意味論を利用できることを要求する。言語名の一覧そのものは表で管理し、共通の機能要件と、言語ごとに確認する結果を以下に示す。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-03-001"></a>RQ-03-001 | C++ | C++アプリケーションから、共通Coreが提供する初期共通基盤のUI機能とMVVM機能を利用できること。 | 現行 |
| <a id="rq-03-002"></a>RQ-03-002 | C# | C#アプリケーションから、共通Coreが提供する初期共通基盤のUI機能とMVVM機能を利用できること。 | 現行 |
| <a id="rq-03-003"></a>RQ-03-003 | Rust | Rustアプリケーションから、共通Coreが提供する初期共通基盤のUI機能とMVVM機能を利用できること。 | 現行 |
| <a id="rq-03-004"></a>RQ-03-004 | Python 3 | Python 3アプリケーションから、共通Coreが提供する初期共通基盤のUI機能とMVVM機能を利用できること。 | 現行 |
| <a id="rq-03-005"></a>RQ-03-005 | C++の例外無効buildとhandler | 例外無効buildでも共通機能を利用でき、失敗を結果として扱えること。例外有効buildではcallback例外の利用者handlerを設定でき、そのhandlerによってABI境界やcallback固有の失敗結果を壊さないこと。 | 初期共通基盤 |
| <a id="rq-03-006"></a>RQ-03-006 | C#の明示破棄と競合 | 明示破棄を繰り返しても二重解放せず、native呼出しと破棄が競合しても呼出し中の対象を失わないこと。callbackの例外処理を利用者が設定でき、元の失敗を識別できること。 | 初期共通基盤 |
| <a id="rq-03-007"></a>RQ-03-007 | Rust safe APIとpanic限界 | 通常のsafe API利用で借用参照を解放したり、期限外に利用したりせず共通機能を扱えること。捕捉可能なpanicをABIへ伝播させず、abortや二重panicで終了するprocessのcleanup完遂は保証対象に含めないこと。 | 初期共通基盤 |
| <a id="rq-03-008"></a>RQ-03-008 | Python明示終了とowner回収 | 明示終了とscope終了による解放を利用できること。管理ownerが回収された場合もnative資源の後始末を管理経路へ引き渡し、owner自身の回収が資源を管理不能にしないこと。 | 初期共通基盤 |
| <a id="rq-03-009"></a>RQ-03-009 | Python通常終了の管理境界 | 明示終了、管理対象のmain/host処理終了、未捕捉main例外、SystemExit、host UI loop終了、wrapper所有worker例外の各経路で終了を要求でき、[通常終了の協調条件](RQ-03_language-support.md#rq-03-015)を満たす管理対象UI threadだけが残って通常終了を妨げないこと。外部hostを使う利用者はmain/hostの管理対象を登録し、その処理終了・loop停止を通知すること。callback例外は種別固有の失敗として扱うこと。 | 初期共通基盤 |
| <a id="rq-03-010"></a>RQ-03-010 | Python即時process終了の除外 | os._exit、fatal error、強制killなどprocessが即時終了する経路ではin-process cleanup完遂を保証しないこと。 | 初期共通基盤 |
| <a id="rq-03-011"></a>RQ-03-011 | 診断・解析の能力と限界 | 静的に解決できる同一ControlのPropertyアクセスを診断できること。解析不能な動的箇所を安全確認済みと表示せず、同じ入力・設定に同じ診断を返し、古い解析結果を最新として返さないこと。 | 初期共通基盤 |
| <a id="rq-03-012"></a>RQ-03-012 | 共通解析診断 | Pythonのlint/type checkと、MCP/CLI/CIの各入口で同じ入力・設定から同じ診断を利用できること。未解決の動的箇所を安全確認済みと表示しないこと。 | 初期共通基盤 |
| <a id="rq-03-013"></a>RQ-03-013 | 初期unload範囲 | 初期版の通常利用ではnative libraryをprocess終了まで保持し、active callback/ticketがある状態のhot unloadとcollectible managed unloadを提供対象に含めないこと。 | 初期共通基盤 |
| <a id="rq-03-014"></a>RQ-03-014 | 言語minimumとbuild基準 | 初期利用基準をC++17/CMake3.28、Rust1.85 edition2024、net10.0、CPython3.13とすること。C# wrapperのライブラリソースはC#14を基準とし、consumerのソース言語版と区別すること。正式supportの処理系/profileを公表し、free-threaded版とPyPy/subinterpreterのsupportを通常版から推定しないこと。 | 初期共通基盤 |
| <a id="rq-03-015"></a>RQ-03-015 | Python正常cleanupの協調条件 | 管理entryの通常return・一般例外・SystemExitと管理host停止でcleanupを要求できること。hostはUI thread終了前に停止通知を接続し、callback/finalizer/handlerの利用者処理は有限に戻り、終了処理を同期待ちするmainとの循環待ちを作らないこと。未登録host・停止不能な利用者処理・即時process終了でcleanup完遂を保証しないこと。 | 初期共通基盤 |
| <a id="rq-03-016"></a>RQ-03-016 | Python基底初期化とoverride範囲 | 管理ownerの基底初期化未実行を検出し、資源取得の前後で明確に失敗できること。close/context/native entryの保護対象をoverride不可とし、任意演算子に一律base callを要求しないこと。 | 初期共通基盤 |
| <a id="rq-03-017"></a>RQ-03-017 | callback markerと検知能力 | callback種別の明示annotationを各言語で利用でき、型・禁止効果・同期/非同期不一致を診断できること。禁止を証明できない経路はUnknownとし、警告とerrorを区別すること。 | 初期共通基盤 |


## 適用境界

承認は要求本文の範囲で完結する。API名・内部データ構造・処理方式の確定を前提にしない。既存ADRによるRust Core・versioned C ABI等の明示的な構成制約は維持する。
