# RQ-04: 公開ABI境界

- 文書版: 0.5
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

4言語が共通のnative runtimeを利用するABI境界に必要な表現と、言語固有の内部表現を境界の外へ出さない制約を定める。固定された表現一覧は表で管理し、要求IDごとに使い道と確認結果を明示する。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-04-001"></a>RQ-04-001 | 固定幅整数 | ABIで扱う整数は幅が定まった整数型で表現できること。呼出側の処理系に依存する幅の整数を共通契約として要求しない。 | 現行 |
| <a id="rq-04-002"></a>RQ-04-002 | `float` / `double` | ABIで単精度と倍精度の浮動小数値を受け渡せること。初期Propertyの型集合とABI全体の対応範囲を区別すること。 | 現行 |
| <a id="rq-04-003"></a>RQ-04-003 | UTF-8の `(pointer, length)` | ABIで文字列をUTF-8のbyte列と明示的な長さで受け渡せること。文字列終端の暗黙規則だけに依存しないこと。 | 現行 |
| <a id="rq-04-004"></a>RQ-04-004 | opaque handle | ABI利用者がCore内部の具体的なobject表現に依存せず、opaque handleで対象を識別できること。 | 現行 |
| <a id="rq-04-005"></a>RQ-04-005 | 明示的な `retain/release` | handleの参照をABI利用者が明示的に保持・解放できること。個別関数で所有参照と借用参照の役割を区別できること。 | 現行 |
| <a id="rq-04-006"></a>RQ-04-006 | `ui_status` | ABI関数の実行結果を、言語に依存しないstatus値で呼出側へ返せること。 | 現行 |
| <a id="rq-04-007"></a>RQ-04-007 | error object | statusだけでは伝えられない失敗情報を、言語固有例外を境界越しに渡さず扱えるerror objectを提供すること。 | 現行 |
| <a id="rq-04-008"></a>RQ-04-008 | `callback + userdata + destroy` | callback登録で関数、利用者状態を表すuserdata、userdata解放用destroy処理を組み合わせて渡せること。言語固有objectやdelegateそのものをABIで保持させないこと。 | 現行 |
| <a id="rq-04-009"></a>RQ-04-009 | ABI version | 利用中のABI versionを呼出側が問い合わせられること。 | 現行 |
| <a id="rq-04-010"></a>RQ-04-010 | feature query | 利用側がABI機能の対応有無を照会できること。未対応機能を利用側が判別できること。 | 現行 |
| <a id="rq-04-011"></a>RQ-04-011 | Rust型、trait、generic、borrow | Rust型、trait、generic、borrowを公開ABIの引数・戻り値・公開構造体に含めない。 | 現行 |
| <a id="rq-04-012"></a>RQ-04-012 | C++ class、STL、RTTI、exception表現 | C++ class、STL型、RTTI情報、C++ exceptionを前提とする型表現を公開ABIに含めない。exceptionの実行時伝播禁止はRQ-04-016で扱う。 | 現行 |
| <a id="rq-04-013"></a>RQ-04-013 | Python object | Python objectを公開ABIの引数・戻り値・公開構造体に含めない。 | 現行 |
| <a id="rq-04-014"></a>RQ-04-014 | C# object / delegate | C# objectまたはdelegateを公開ABIの引数・戻り値・公開構造体に含めない。 | 現行 |
| <a id="rq-04-015"></a>RQ-04-015 | Rust panic | Rust panicをABI境界の外へ伝播させない。 | 現行 |
| <a id="rq-04-016"></a>RQ-04-016 | C++ exception | C++ exceptionをABI境界の外へ伝播させない。 | 現行 |
| <a id="rq-04-017"></a>RQ-04-017 | Python exception | Python exceptionをABI境界の外へ伝播させない。 | 現行 |
| <a id="rq-04-018"></a>RQ-04-018 | 安全な参照を発行できない場合 | 安全に識別できる所有参照を新たに発行できない場合は取得・生成を失敗させ、既存の参照を別対象へ誤って解決しないこと。 | 初期共通基盤 |
| <a id="rq-04-019"></a>RQ-04-019 | 参照の種類・所属の拒否結果 | 無効な参照、期待する対象種類の不一致、異なるRuntime所属の組合せを呼出し側が失敗理由として区別でき、拒否によって対象状態を変更しないこと。 | 初期共通基盤 |
| <a id="rq-04-020"></a>RQ-04-020 | UTF-8文字列の受渡し結果 | 埋め込みNULを含む有効なUTF-8文字列を指定長のまま扱えること。不正UTF-8を拒否し、暗黙のUnicode正規化や別文字への置換をしないこと。 | 初期共通基盤 |
| <a id="rq-04-021"></a>RQ-04-021 | buffer不足時の結果 | 出力bufferの容量が不足する場合は必要容量を知ることができ、bufferへ一部だけを書き込まないこと。容量照会と次の読取りの間の同一snapshot保証があるかをAPIごとに判断できること。 | 初期共通基盤 |
| <a id="rq-04-022"></a>RQ-04-022 | error詳細を生成できない失敗 | 失敗詳細を生成できない資源不足時にも元の失敗分類を保持すること。error snapshotは保持中に別操作の結果で書き換わらず、未知のstatus/domain/codeも元の数値として取得できること。 | 初期共通基盤 |
| <a id="rq-04-023"></a>RQ-04-023 | 利用者定義エラーの自動採番 | 利用者が失敗理由に名前付きの定義と自動採番を利用できること。公開した理由の識別値と意味を再採番・再利用せず、共通定義を使う場合は言語間で一致すること。 | 初期共通基盤 |
| <a id="rq-04-024"></a>RQ-04-024 | 機能照会と互換性 | 提供されない機能を利用前に識別でき、未知の機能識別子は未対応として扱えること。公開済み機能識別子とstatusの意味を再利用せず、wrapperが必要とするRuntime互換条件を判断できること。 | 初期共通基盤 |
| <a id="rq-04-025"></a>RQ-04-025 | 単一操作の準備失敗 | 入力検証、必要な内容の保持、必須の結果資源の準備に失敗した操作は、その操作に属するCore状態・通知を部分更新しないこと。 | 初期共通基盤 |
| <a id="rq-04-026"></a>RQ-04-026 | 独立操作の結果維持 | 先に成功した独立操作と利用者callbackの副作用を自動的に取り消さないこと。 | 初期共通基盤 |
| <a id="rq-04-027"></a>RQ-04-027 | エラー機械識別と説明 | 失敗をstatus/domain/codeで機械識別でき、messageは説明用として利用できること。causeとdiagnosticを区別し、保持した失敗snapshotの利用期間を判断できること。 | 初期共通基盤 |
| <a id="rq-04-028"></a>RQ-04-028 | Runtime release互換 | 安定版RuntimeはMAJOR.MINOR.PATCHで識別し、majorはABI互換系列を示すこと。同majorのminorは後方互換追加、patchは互換修正とすること。wrapperが必要とするminimum互換条件を公表すること。 | 初期共通基盤 |
| <a id="rq-04-029"></a>RQ-04-029 | F32変換の外部結果 | 単精度・倍精度を明示変換できること。精度一致必須または最近接偶数丸めを指定でき、有限値の範囲外を拒否すること。NaN payloadの保存は保証せず、符号付きzeroとinfinityの意味を保つこと。 | 初期共通基盤 |
| <a id="rq-04-030"></a>RQ-04-030 | 初回stableとwrapper互換 | 初回stableをRuntime1.0.0/ABI1とし、pre-releaseをrc.Nで識別できること。wrapper versionが独立でも必要Runtime/ABI/featureを判断できること。 | 初期共通基盤 |
