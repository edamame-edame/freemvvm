# RQ-06: Threadと非同期処理

- 文書版: 0.5
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

UI状態を扱うthreadの境界、worker要求の引渡し、共有データの安全性、非同期Commandの終了結果を定める。thread間の共有可否と操作結果を、処理系固有の暗黙動作に依存させない。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-06-001"></a>RQ-06-001 | UI thread制約 | Runtime作成時に結び付いたUI thread上でUI状態の作成・読取・変更・購読操作を行うこと。UI操作を別threadから直接実行した場合は明確なthread違反として扱い、失敗操作でUI状態を変更しないこと。 | 現行 |
| <a id="rq-06-002"></a>RQ-06-002 | workerからのdispatch | workerがUI更新を要求できる引渡し手段を提供すること。要求の受付とUI上での実行完了を区別し、引渡し先でUI操作を直列に処理すること。Runtime停止後など実行できない要求を成功扱いにしないこと。 | 現行 |
| <a id="rq-06-003"></a>RQ-06-003 | thread間のデータ競合防止 | 複数threadから変更可能な共有状態は、同時変更を安全に扱える同期を備えること。workerから変更させない状態はread-onlyとして公開するか、値のsnapshot/copyで渡すこと。GIL等、特定言語処理系の暗黙の直列化だけを排他制御の根拠にしない。 | 現行 |
| <a id="rq-06-004"></a>RQ-06-004 | 非同期Commandの終端 | 非同期Commandの実行中状態と、成功・失敗・キャンセルの終端結果を区別すること。実行はUI threadを長時間占有せず、キャンセル要求とworkerの実際の終了結果を区別し、古い実行から遅れて届いた通知が現在の実行状態を上書きしないこと。 | 現行 |
| <a id="rq-06-005"></a>RQ-06-005 | callback/event中の終了要求 | callbackまたはUI event処理中にもRuntime終了を要求できること。現在の処理を完了させた後、未開始の通常作業より優先して終了処理を実行すること。 | 初期共通基盤 |
| <a id="rq-06-006"></a>RQ-06-006 | 終了要求の受付と完了 | 非同期の終了要求は受付後に戻り、終了完了を待たないこと。同期指定でもcallback/event中は受付後に戻り、workerからの同期指定はUI threadでの終了完了後に戻ること。受付済みと完了済みを区別できること。 | 初期共通基盤 |
| <a id="rq-06-007"></a>RQ-06-007 | 停止したUI loopへの同期要求 | UI処理を実行できないことが確定した場合は、同期終了要求を無期限に待ち続けず、未完了と待機終了理由を呼出し側が識別できること。待機終了を資源解放完了として扱わないこと。 | 初期共通基盤 |
| <a id="rq-06-008"></a>RQ-06-008 | Command実行受付と結果 | Commandの実行受付成功と業務処理の成功・失敗を区別できること。受付後の開始処理の失敗はその実行の失敗として観測でき、受付前の失敗では実行を開始しないこと。 | 初期共通基盤 |
| <a id="rq-06-009"></a>RQ-06-009 | 実行取消の独立性 | 同じ実行への重複取消と終端済みの同じ実行への取消は追加効果を起こさず、古い実行へ誤適用しないこと。 | 初期共通基盤 |
| <a id="rq-06-010"></a>RQ-06-010 | Command利用終了 | Commandの利用終了は新規実行を止め取消を要求し、worker終了をUI threadで待たないこと。所有参照の破棄だけでは利用終了を要求しないこと。 | 初期共通基盤 |
| <a id="rq-06-011"></a>RQ-06-011 | 非同期進捗と終端 | 中間進捗は最新値への集約を許し、終端結果は進捗と独立して一度だけ反映すること。過去実行および終端後の通知で現在状態を変更しないこと。 | 初期共通基盤 |
| <a id="rq-06-012"></a>RQ-06-012 | 終了要求の完了観測 | 受付済み終了要求の未完了・完了・host実行不可と理由をthreadに依存せず観測できること。観測参照の破棄で終了要求を取り消さず、停止から同UI hostが復旧した場合は明示再試行できること。 | 初期共通基盤 |
| <a id="rq-06-013"></a>RQ-06-013 | Command進捗値 | Commandの単一channelの進捗を明示報告・読取りできること。0～1の正規化値と未定を区別し、中間sampleの全保存は保証しないこと。終端結果を進捗の集約で失わないこと。 | 初期共通基盤 |
