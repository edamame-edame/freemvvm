# RQ-02: Core機能

- 文書版: 0.5
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

Coreが提供する機能を、機能ごとに満たす条件と初期共通基盤と次段階の違いは表の対象段階に示す。詳細な公開APIや内部構造は要求では固定しない。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-02-001"></a>RQ-02-001 | Object | UI要素やMVVM機能を、利用者が一貫して参照・操作できるCore上の対象として扱えること。対象の所有・共有・破棄に関する契約が定義され、利用中の対象が意図せず消失せず、利用終了後に保持され続けないこと。 | 現行 |
| <a id="rq-02-002"></a>RQ-02-002 | Property | ViewModelとUIが値を共有し、値の変更を相手側から観測できること。宣言された値種別と整合しない更新は受け入れず、値が実際に変わらない更新で不要な変更通知を生じさせないこと。 | 現行 |
| <a id="rq-02-003"></a>RQ-02-003 | Binding | OneTime、OneWay、TwoWayの更新方向を利用できること。初期値の同期、変更の伝播、検証失敗、循環または競合する接続、解除後の伝播停止について一貫した結果を提供すること。複数Propertyをまとめる一般transactionや自動rollbackは要求しない。 | 現行 |
| <a id="rq-02-004"></a>RQ-02-004 | Command | UI操作から処理を実行でき、実行可否と実行中・完了・失敗・キャンセルの状態を利用者へ示せること。非同期処理の完了や結果がUIへ反映され、同一処理の再入規則が予測可能であること。 | 現行 |
| <a id="rq-02-005"></a>RQ-02-005 | Collection | 次段階で、項目の追加・削除・並べ替え等の集合状態を保持し、変更を利用側が把握できること。項目の識別は順序位置の変化だけで別項目に切り替わらないこと。対象範囲は[次段階のCollectionModel要求](RQ-09_ui-scope.md#rq-09-019)に従う。 | 現行 |
| <a id="rq-02-006"></a>RQ-02-006 | Selection | 次段階で、項目集合に対する選択状態と現在項目を扱えること。選択状態・現在項目・キーボードフォーカスの意味を混同せず、対象項目の削除後に存在しない項目が選択中または現在項目として残らないこと。対象範囲は[次段階のSelectionModel要求](RQ-09_ui-scope.md#rq-09-020)に従う。 | 現行 |
| <a id="rq-02-007"></a>RQ-02-007 | Visual Tree | Widgetの視覚的な親子構造を構成し、構造に沿った描画・入力対象の決定を可能にすること。アプリが組み立てる意味上の階層と描画都合の内部要素を区別し、内部表現だけで意味上の親子関係を不意に変えないこと。 | 現行 |
| <a id="rq-02-008"></a>RQ-02-008 | Layout | 利用可能な領域とWidgetの配置規則に基づいて、各Widgetの必要サイズと表示位置を決定できること。親子関係に応じてレイアウトを再計算し、結果をPlatform表示領域へ反映できること。 | 現行 |
| <a id="rq-02-009"></a>RQ-02-009 | Input | Platformから届く入力を共通UI機能で扱い、対象Controlの操作へ結び付けられること。少なくとも初期共通基盤ではキーボード入力とTextBox編集入力を利用でき、入力検証の結果を利用者へ保持・伝達できること。 | 現行 |
| <a id="rq-02-010"></a>RQ-02-010 | Focus | 現在キーボード・文字入力を受けるControlを識別し、フォーカス変更をControlとPlatform間で同期できること。Focus状態はSelection状態と区別されること。 | 現行 |
| <a id="rq-02-011"></a>RQ-02-011 | IME | IMEの未確定入力と確定入力を区別し、変換中の編集状態を保持した上で、確定候補を入力検証へ渡せること。IMEを備えるPlatformで日本語等の変換入力を利用できること。 | 現行 |
| <a id="rq-02-012"></a>RQ-02-012 | Error handling | Core/API操作と非同期処理の失敗を呼出し側が識別し、原因に応じて処理できる形で伝えること。言語固有の例外やpanicを共通公開境界の外へ漏らさないこと。 | 現行 |
| <a id="rq-02-013"></a>RQ-02-013 | Lifetime管理 | Core対象・callback・Platform資源の利用期間と解放契機を明確にし、所有者が終了した対象や不要になった内部資源を保持し続けないこと。終了処理がUI資源の解放を行えること。 | 現行 |
| <a id="rq-02-014"></a>RQ-02-014 | UI thread管理 | UI状態の読み書きとPlatform操作を安全なUI実行スレッドで行えること。workerから要求されたUI更新は安全に引き渡され、thread間でデータ競合を起こさないこと。 | 現行 |
| <a id="rq-02-015"></a>RQ-02-015 | Runtime停止後の利用境界 | Runtime終了後はUI機能を利用できず、終了済みであることを識別できること。残存する所有参照は解放でき、不変なエラー情報はその参照の利用期間内に読み取れること。 | 初期共通基盤 |
| <a id="rq-02-016"></a>RQ-02-016 | Runtime終了の再要求 | Runtime終了が完了した後に再度終了を要求しても成功し、利用者データの後始末や資源解放を重複して実行しないこと。 | 初期共通基盤 |
| <a id="rq-02-017"></a>RQ-02-017 | 初期Propertyの値型範囲 | 初期Propertyで真偽値、符号付き64-bit整数、有効なUTF-8文字列、倍精度浮動小数値、規定範囲の十進値を利用できること。初期範囲にnullable値・任意言語object・カスタム構造体値を含めず、それらをゼロや空文字列へ読み替えないこと。 | 初期共通基盤 |
| <a id="rq-02-018"></a>RQ-02-018 | F64の同値と保持結果 | 倍精度値はNaNと無限大を受け入れること。同符号の無限大、正負のゼロ、NaN同士はそれぞれ同値とし、同値設定では既存の格納表現を変えず変更通知を出さないこと。 | 初期共通基盤 |
| <a id="rq-02-019"></a>RQ-02-019 | 十進値の範囲と同値 | 十進値は符号・0～31のscale・0～2^58−1の係数で表せる範囲を正確に扱い、範囲外を黙って丸めないこと。1.0と1.00、正負のゼロは数値として同値とし、同値設定では既存の格納表現と通知状態を維持すること。 | 初期共通基盤 |
| <a id="rq-02-020"></a>RQ-02-020 | 同値設定時の検証 | 現在値と同値を設定する場合も登録済みの値検証を適用すること。受理された同値設定は現在値の格納表現を置き換えず、値変更通知を生じさせないこと。 | 初期共通基盤 |
| <a id="rq-02-021"></a>RQ-02-021 | Validator登録条件 | 一つのPropertyに登録できる同期Validatorは最大一つとし、登録だけでは現在値を再検証しないこと。重複登録失敗で既存登録を失わないこと。 | 初期共通基盤 |
| <a id="rq-02-022"></a>RQ-02-022 | 文字列と数値の明示converter | 次段階でUTF8と整数・十進値の明示parse/formatを提供すること。初期の文法はlocale非依存の符号・数字・十進点とし、表現不能を黙って丸めないこと。Bindingの暗黙型変換は追加しないこと。 | 次段階 |
