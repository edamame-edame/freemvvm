# RQ-17: WebViewエンジンプラグイン

- 文書版: 1.0
- 状態: 承認済み（利用者、2026-10-24）
- 更新日: 2026-10-24
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

Markdown、HTML、CSSおよび軽量スクリプトからWeb表示を構成・描画し、将来のView用言語および4言語ラッパー（C++ / C# / Rust / Python 3）から共通に埋め込み利用できるWebViewエンジンプラグインの要求を定める。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、承認は要求本文の範囲で完結する。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-17-001"></a>RQ-17-001 | OS非依存の純粋Core描画 | WebViewはOS固有ブラウザ部品（WebView2、WebKitGTK等）に依存せず、Core自身のエンジンによって文書解析・スタイル解決・レイアウト・描画生成を行い、Windows、デスクトップLinux、組み込みLinuxの各対象環境で一貫した表示意味論を提供すること。 | 現行 |
| <a id="rq-17-002"></a>RQ-17-002 | 外部crate非依存の純粋Rust構成 | WebViewエンジンは外部サードパーティ製crateに依存せず、標準ライブラリのみで文書解析・スタイル計算・レイアウト・スクリプト実行を構成し、ライセンス純度とサプライチェーン整合性を維持すること。 | 現行 |
| <a id="rq-17-003"></a>RQ-17-003 | Markdown文書の表示 | CommonMarkおよびGitHub Flavored Markdown（GFM）の主要構造（見出し、段落、強調・取消線、箇条書き・番号付きリスト、表、コードスパン・コードブロック、引用、水平線、リンク）を入力として受け取り、構造化された文書として描画できること。 | 現行 |
| <a id="rq-17-004"></a>RQ-17-004 | HTML・CSS文書の表示 | HTML文書構造とCSSスタイル規則（ボックスモデル、色・背景、フォント・テキスト装飾、Block / Inline / Flex / Table配置、状態擬似クラス）を解決し、指定されたスタイルとレイアウトに従って描画できること。未知の要素や未対応CSSプロパティで異常終了せず、定義された既定スタイルまたは無視規則へ安全にフォールバックすること。 | 現行 |
| <a id="rq-17-005"></a>RQ-17-005 | UI Tree所属とLayout統合 | WebViewはUI Tree上のWidgetとしてWindowやStackPanel等のContainerへ配置でき、親から与えられた利用可能領域と論理寸法（DIP）に従って自身の大きさと内部スクロール範囲を決定できること。Detached subtreeの維持・再所属規則は共通Widget契約に従うこと。 | 現行 |
| <a id="rq-17-006"></a>RQ-17-006 | PropertyとBindingによる内容・入力同期 | 文書ソース（MarkdownまたはHTML）および追加CSSスタイルシートをUTF-8 PropertyおよびOneWay Binding経由で動的に更新できること。また、WebView内のフォーム入力要素の値変更をTwoWay BindingおよびProperty Validatorと連携させ、確定値と検証拒否理由を観測できること。 | 現行 |
| <a id="rq-17-007"></a>RQ-17-007 | リンク・アクションとCommand連携 | WebView内のリンク選択、ボタン操作、フォーム送信、またはスクリプトからの明示アクションをCoreのCommand起動へ接続でき、Commandの実行可否（CanExecute）および再入防止規則に従うこと。 | 現行 |
| <a id="rq-17-008"></a>RQ-17-008 | 軽量スクリプト実行とDOM・MVVM連携 | WebView内で軽量スクリプト（JavaScriptサブセット）をサンドボックス実行でき、DOM要素の参照・内容/属性/クラスの変更・イベント購読、および公開許可されたViewModel Property参照・更新・Command起動を行えること。スクリプトによるDOM変更は再スタイル・再レイアウト・再描画へ一貫して反映されること。 | 現行 |
| <a id="rq-17-009"></a>RQ-17-009 | 決定論的リソース制限とサンドボックス境界 | 非信頼または過大な文書・スタイル・スクリプト入力に対し、DOMノード数、ネスト深さ、CSSセレクタ評価、およびスクリプトの1実行あたり命令ステップ数・コールスタック深さ・メモリ使用量の上限を設定・強制できること。上限超過時はUIスレッドを凍結させず当該処理を中断し、直前の有効な公開状態または定義されたエラー状態を維持すること。 | 現行 |
| <a id="rq-17-010"></a>RQ-17-010 | オフライン既定と外部資源取得の遮断 | WebViewは既定で暗黙の外部ネットワーク通信（HTTP/HTTPS取得等）やOSファイルシステム・プロセスへの直接アクセスを一切行わないこと。外部リソース参照はホスト側が明示登録したリゾルバまたはインラインデータのみに限定し、未許可のURIスキームは拒否すること。 | 現行 |
| <a id="rq-17-011"></a>RQ-17-011 | 4言語ラッパーとView言語からの共通埋め込み | versioned C ABIを介してC++、C#、Rust、Python 3の各言語ラッパーおよび将来のView用言語から同一の意味論でWebViewを生成・設定・破棄でき、所有権・スレッド拘束・エラー報告が既存の共通契約に従うこと。 | 現行 |
| <a id="rq-17-012"></a>RQ-17-012 | WebView内部要素のAccessibility公開 | WebView内の意味構造（見出し、段落テキスト、リンク、ボタン、入力欄、表）をCoreのAccessibility意味情報（role、name、state、value、focus、action）へ写像し、支援技術から参照・操作できること。 | 現行 |
