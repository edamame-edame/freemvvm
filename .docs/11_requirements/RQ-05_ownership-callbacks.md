# RQ-05: 所有権とcallback

- 文書版: 0.9
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

ABIを介して扱うhandle、buffer、callbackの所有者と有効期間を、API利用者が判断できることを要求する。各RQ IDには利用者が得られる能力または外部動作の保証を記載する。

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-05-001"></a>RQ-05-001 | 所有参照の識別 | 利用者が、APIに渡す参照またはAPIから受け取る参照について、借用参照か所有参照か、および破棄責任を判断できること。 | 現行 |
| <a id="rq-05-002"></a>RQ-05-002 | 所有参照の取得と破棄 | 同じ対象の所有参照を複数取得し、それぞれ独立して破棄できること。ある参照の破棄で他の有効な所有参照を無効にしないこと。Subscription、Binding、Validatorなどの登録は、その登録の所有参照を破棄しただけでは解除されず、当該機能の解除条件またはRuntime終了まで登録の外部動作を維持すること。 | 現行 |
| <a id="rq-05-003"></a>RQ-05-003 | 所有参照の有効期間 | 所有参照は明示的な破棄まで保持できること。Runtime終了後はUI利用を終了し、残る所有参照の解放と不変エラー情報の読取りを引き続き行えること。利用終了にthreadまたは順序の条件がある場合、利用者がその条件を判断できること。 | 現行 |
| <a id="rq-05-004"></a>RQ-05-004 | 文字列・配列・bufferの利用期間 | 利用者が、入力文字列・配列、出力buffer、callbackへ渡される値の所有者と利用可能な期間を判断できること。非同期処理に渡した入力は、その処理が必要とする期間、正しい内容で利用できること。 | 現行 |
| <a id="rq-05-005"></a>RQ-05-005 | pointerの借用期間 | 利用者が入力pointer、出力buffer、callback引数pointerのそれぞれについて、利用可能な期間を判断でき、その期間内に値を利用できること。 | 現行 |
| <a id="rq-05-006"></a>RQ-05-006 | callback登録の有効期間と解除条件 | callbackの登録が成功した場合、利用者が当該APIの登録終了条件を判断でき、その条件が成立するまでcallbackが呼出可能であること。登録に関連する所有参照の破棄だけでは登録が解除されないこと。 | 現行 |
| <a id="rq-05-007"></a>RQ-05-007 | callback解除完了後の動作 | callback解除が完了した後は新しいcallback呼出しが始まらないこと。解除時点ですでに実行中のcallbackがある場合、そのcallbackが終了するまではcallbackに必要な利用者データを利用可能に保つこと。 | 現行 |
| <a id="rq-05-008"></a>RQ-05-008 | userdataの後始末 | callback登録が成功した場合、登録が無効となりuserdataを使うcallbackが終了した後に、利用者が指定した後始末処理を一度だけ実行すること。登録に失敗した場合は、利用者がuserdataの後始末責任を保持すること。callbackが一度も実行されない場合にも、登録成功後の後始末結果を利用者が判断できること。 | 現行 |
| <a id="rq-05-009"></a>RQ-05-009 | callback中に利用できる操作 | 利用者がcallbackの種類ごとに実行可能なAPI操作と、実行できない操作の結果を判断できること。callback中に発生した通知は、実行中callbackが終了する前に別のcallback呼出しとして割り込まないこと。 | 現行 |
| <a id="rq-05-010"></a>RQ-05-010 | 任意threadの参照取得・破棄 | 所有参照を取得・破棄する操作を任意threadから利用できること。UI資源の最終解放が操作の戻りより遅れる場合は、その操作の成功と解放完了を区別できること。 | 初期共通基盤 |
| <a id="rq-05-011"></a>RQ-05-011 | 破棄済み参照への重複破棄 | 破棄済みの同じ所有参照を再度破棄しようとした場合は失敗し、他の有効な所有参照と対象状態に影響しないこと。 | 初期共通基盤 |
| <a id="rq-05-012"></a>RQ-05-012 | 破棄失敗時の参照保全 | 所有参照の破棄を受け付けられなかった場合はその参照の所有を維持し、後から解放を再試行できること。言語側の自動後始末経路でも、解放に失敗した参照を管理不能なまま失わないこと。 | 初期共通基盤 |
| <a id="rq-05-013"></a>RQ-05-013 | 判定callback中の禁止操作 | ValidatorとTextBox入力判定callbackでは同じRuntimeのUI状態変更と自己登録解除を許さず、禁止操作を状態変更前に拒否すること。入力拒否とcallback自体の異常を区別できること。 Runtime終了要求の受付はこの禁止の対象外とし、現在callback終了後の終了要求規則に従うこと。 | 初期共通基盤 |
| <a id="rq-05-014"></a>RQ-05-014 | 通知例外後の継続 | 通知callbackで捕捉可能な言語例外が起きた場合、失敗を診断し、他の有効な通知対象の配信を継続すること。 | 初期共通基盤 |
| <a id="rq-05-015"></a>RQ-05-015 | 判定callbackの異常 | 戻り値を持つcallbackでは各種別の失敗結果を得られ、通常の入力拒否とcallback異常を区別できること。 | 初期共通基盤 |
