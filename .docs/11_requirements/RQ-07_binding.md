# RQ-07: Binding

- 文書版: 0.7
- 状態: 承認済み（利用者、2026-10-17）
- 更新日: 2026-10-17
- 入口: [要求仕様索引](reqirements-specification.md)

## 概要

Bindingの種類、値伝播の方向・時点・順序、失敗、解除の結果を定める。各RQ IDが示す独立条件と、

本章は提供機能・利用条件・外部から観測できる結果を定める。各IDの対象段階を区別し、将来候補の列挙を採用承認とはしない。

## 要求本文

| 要求ID | 項目 | 要求詳細 | 対象段階 |
| --- | --- | --- | --- |
| <a id="rq-07-001"></a>RQ-07-001 | OneTime | 接続作成時にsourceの現在値をtargetへ一度だけ反映し、その後のどちら側の変更も相手へ伝播しないこと。 | 現行 |
| <a id="rq-07-002"></a>RQ-07-002 | OneWay | 作成時にsourceからtargetへ同期し、以後sourceの変更をtargetへ伝えること。targetの直接変更はsourceへ返さず、次のsource変更まではtarget側で観測できること。 | 現行 |
| <a id="rq-07-003"></a>RQ-07-003 | TwoWay | 作成時はsourceからtargetへ同期し、以後どちら側の直接変更も相手へ伝えること。同じ外側処理中に両方が直接変更された場合は、最後に成功した直接変更の値を両側で観測すること。 | 現行 |
| <a id="rq-07-004"></a>RQ-07-004 | 更新方向 | 各Binding modeのsource/target方向と、直接変更が逆向きへ戻るか否かを明示すること。方向の意味をwrapperごとに変えないこと。 | 現行 |
| <a id="rq-07-005"></a>RQ-07-005 | 更新タイミング | setterが成功したProperty自身のgetterは新値を直ちに返すこと。Binding先への伝播は外側のUI処理が戻った後に行い、同一callback中の相手側readでは旧値の場合があることを一貫して扱うこと。 | 現行 |
| <a id="rq-07-006"></a>RQ-07-006 | 更新順序 | 同じ処理区間の複数source更新は最終値を伝播すること。該当する配信回ではBinding伝播を外部Property通知より先に完了し、Bindingによる変更の通知を再帰させないこと。 | 現行 |
| <a id="rq-07-007"></a>RQ-07-007 | 循環Binding | 初期契約のBindingグラフで自己接続・有向循環、または一つのtargetへ複数のOneWay入力元を作る接続を受け入れないこと。拒否する接続の登録により既存値や接続状態を変えないこと。 | 現行 |
| <a id="rq-07-008"></a>RQ-07-008 | 再入時の扱い | 通知処理から生じた更新を同じ通知処理へ再帰的に割り込ませず、後続の配信で反映すること。反復更新があってもUIへ制御を返せ、非収束の診断・停止対象を識別できること。 | 現行 |
| <a id="rq-07-009"></a>RQ-07-009 | 確定値と独立更新 | 失敗したProperty更新は当該Propertyの確定値を変えず、成功したProperty更新で確定した値は、後続する別Property更新の失敗を理由に取り消さないこと。 | 現行 |
| <a id="rq-07-010"></a>RQ-07-010 | Binding検証の結果 | Binding作成時の初期同期でtargetが値を拒否した場合、作成失敗を呼出側へ返し、targetの確定値と接続状態を変更しないこと。作成後の伝播でtargetが値を拒否した場合、先行するsource setterの成功を取り消さず、sourceの確定値とtargetの従前の確定値を保ち、拒否内容をBinding固有の機械可読なエラーとして観測可能にすること。次の有効な伝播で値を同期し、現在のBindingエラーを解消すること。 | 現行 |
| <a id="rq-07-011"></a>RQ-07-011 | Binding解除 | Bindingの所有参照の破棄だけでは接続を解除せず、明示解除またはRuntime終了まで伝播を維持すること。解除後は将来および保留中の変更をその接続経由で伝播せず、各Propertyの確定値を維持すること。 | 現行 |
| <a id="rq-07-012"></a>RQ-07-012 | 購読の初期通知・順序 | Property購読時は初期変更通知を送らず、現在値を読取り操作で得られること。同じ配信対象の購読者は登録順に通知され、配信中に追加した購読はその配信回に割り込まないこと。 | 初期共通基盤 |
| <a id="rq-07-013"></a>RQ-07-013 | 長期保留の診断設定 | 長期保留の診断閾値を利用者が設定・無効化でき、既定値を5秒とすること。長期保留の検出だけを理由に更新連鎖を停止・破棄せず、同じ連鎖の同じ保留状態を重複診断し続けないこと。 | 初期共通基盤 |
| <a id="rq-07-014"></a>RQ-07-014 | 非収束診断と回復 | 非収束と判断できた更新連鎖のみを停止し、独立した連鎖と既に確定した値を維持すること。長期保留と非収束停止を区別して観測でき、保留更新の破棄と停止連鎖の再開を明示的に選べること。 | 初期共通基盤 |
| <a id="rq-07-015"></a>RQ-07-015 | 同じBindingの重複接続 | 同じsourceから同じtargetへの重複Binding接続を拒否し、失敗前の値・接続・通知を維持すること。 | 初期共通基盤 |
| <a id="rq-07-016"></a>RQ-07-016 | 初期検証の同期範囲 | 初期Property/View入力検証は短時間の同期結果を扱い、Core管理の非同期検証・pending状態は提供しないこと。長時間・remote検証と古い結果の識別はアプリ側の非同期処理・状態で扱えること。複数Propertyの一括再評価・共通表示の追加は含めないこと。 | 初期共通基盤 |
| <a id="rq-07-017"></a>RQ-07-017 | WatchDog設定適用時点 | 診断閾値の変更は既存の保留連鎖にも適用し、最初に保留した時点からの経過に対して評価すること。無効化で連鎖の値や保留作業を捨てないこと。 | 初期共通基盤 |
