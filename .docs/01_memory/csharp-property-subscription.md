# Scope: C# Property notification Subscription

- C# public subscription uses `UiProperty<T>.TrySubscribe(Action)`. Notification carries no copied value; read the latest Property value through `TryGet()` inside the callback. Registration does not send an initial callback.
- Keep subscription cancellation separate from handle ownership: `TryCancel()` stops new callbacks, while `TryClose()`/`Dispose()` releases only the owned subscription handle. Releasing the handle alone leaves the Runtime registration active.
- Each long-lived C callback uses a static trampoline and a `GCHandle`-rooted state. On registration failure managed code frees the root; after registration success the ABI destroy callback owns the one-time release, after in-flight callback completion.
- The callback failure handler belongs to one Runtime. Handler records are atomically replaced; an old registration may clear only its own record, and callbacks that already captured the old record keep it alive to completion. If no handler exists or the handler throws, call `System.Diagnostics.Trace.TraceError` once and contain exceptions from Trace listeners at the ABI boundary.
- Keep the C ABI consumer test on a Runtime with an actual registered UI loop bridge and dispatch turns. A no-loop Runtime correctly rejects shutdown and does not deliver queued notifications, so it cannot prove end-to-end callback delivery.
- Focused fake-ABI and real C ABI consumer entrypoints are `.venv/Scripts/python.exe tools/dev.py csharp-property-test` and `... csharp-property-consumer-test`. `tools/dev.py check` includes both; `tools/dev.py minimum` verifies the Rust minimum toolchain in the bootstrap environment.
