# Scope: WebView Engine Plugin Architecture and Governance

- **Repository Integration**: WebView is implemented inside the `freemvvm` repository (`crates/webview` or `crates/core-runtime` + `crates/c-abi` + 4 language wrappers in `wrappers/{cpp,csharp,rust,python}` + `.docs/` specifications), sharing the versioned C ABI (`ui_abi_1_*`) and handle/property/command model.
- **Zero External Crate Policy**: Like `crates/core-runtime` and `crates/c-abi`, the WebView engine (Markdown parser, HTML tokenizer/tree builder, CSS parser/selector/cascade, Web box/inline/flex/table layout, DisplayList/`SceneSnapshot` generation, and lightweight Script/JS VM) is implemented in pure Rust from scratch with zero third-party runtime dependencies (`edition = "2024"`, `rust-version = "1.85"`).
- **OS-Independent Core Rendering**: Following `ADR-0001` and `13_detail_design/platform/`, WebView does not wrap OS-native browser engines (WebView2/WebKitGTK). It computes layout in `f64` DIP via `LayoutEngine`/`TextService` and emits `SceneSnapshot` drawing primitives and `AxSnapshot` accessibility trees so Windows x64, Linux x64, and Embedded Linux (DRM/KMS, Wayland, X11, framebuffer) behave identically.
- **Feature Scope & Roadmap**: Covers CommonMark/GFM Markdown, HTML/CSS rendering, MVVM `Property`/`Binding`/`Command` integration, and a sandboxed deterministic Script/JS engine with strict step/memory/depth budgets and no arbitrary network/OS access by default.
- **Document & Approval Discipline**: Follow `RQ -> BD -> (DD + SD) -> (RT/UT + software)` strictly. Upstream `RQ` documents must never link downward to `BD`/`DD`/`SD`/tests/code, and `crates/c-abi/include/freemvvm/abi.h` must only declare symbols actually exported by `crates/c-abi/src/lib.rs`.
