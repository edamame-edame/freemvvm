# [Python wrapper / UI Controls prerequisites]

- Python wrapper surfaceを実装計画に載せる前に、DDの公開API一覧・source class一覧・unit inventoryを照合する。Python Runtime/Property完了はBinding/Commandの存在を意味しない。
- 0.0.1 release計画はPythonを含む4言語すべてにProperty/Binding/Command/UI Control vertical sampleを要求する。Python側にはRuntime/Propertyまであり、Binding/AsyncCommand/Control/Window facadeは未実装。
- `impl-python/runtime-wrapper`は`impl-rust/core-ui-controls-c-abi`を祖先に持つ。C# UI Controlsは`impl-csharp/ui-controls-wrapper`で別途完了済みだが、Python branchへmergeせず、要求・共通C ABI・Python DDをPython実装の根拠にする。
- UI Controls plan v0.1がBinding/Commandを「既存」と誤認したため、実装開始前にv0.2でBinding/AsyncCommandを先行依存unitとして追加した。計画scopeの承認はDD/test design/implementation approvalと別に管理する。
- Binding wrapperは承認済みRQ-07と共通C ABIを正本とする。ABI上OneTimeは成功時Binding handle 0、OneWay/TwoWayは所有handleを返し、handle releaseだけでは接続を解除しない（明示cancelまたはRuntime shutdown）。Python DD v1.7とwrapper test design v0.9は2026-10-26に文書全体が承認済み。`UNIT-WRAP-PY-BINDING-001`はfake ABI 29件・実C ABI consumer・Windows local `check`/`minimum`・Windows/Linux CI run 40212415054が成功しcomplete。Command以降の実装は別unit・別承認。
- Python AsyncCommandは承認済みC ABIの`runtime_post`でterminal completionをUIへ戻せる。Command専用progress ABIはなく、既存Command DDは通常Property更新をpost経由で行う形を許す。Python DD v1.8は`CommandOperation.post(callback, *args)`で最小dispatchを提供し、専用progress object/executor/asyncio統合は増やさない。計画・DD v1.8・test design v1.0は2026-10-26に文書単位で承認され、`UNIT-WRAP-PY-COMMAND-001`はplanned登録済み。実装開始は未承認。
- Python AsyncCommand実装では、start callback rootがRuntime owner tokenを独立保持し、C destroy thunkはrootをregistry lock中に破棄せずsafe-point retire queueへ移す。worker operationのterminal post受付後にworkerが`close()`を呼んでも、UI completion callbackが済むまではCommand/Runtime leaseを保持する。C ABI consumerはhost event scope内executeとsuccess/failure/cancel/re-execute/Property postを通して検証する。
- `UNIT-WRAP-PY-COMMAND-001`はfake API 4件、実C ABI consumer、Windows local check/minimumと実装SHA `aaf1ce68d3cd090c93631bdd065b3678a687d010`のWindows/Linux CI run 40214188291成功後にcomplete。
