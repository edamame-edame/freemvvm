# Memory category: Platform presentation backend selection API

- 更新: 2026-11-10
- スコープ: backend selector API・RQ-11-025 test mapping設計と後続実装計画
- 参照先: [selector設計レビュー](../20_todo/presentation-backend-selector-api-test-review.md)、[implementation plan](../20_todo/backend-selector-implementation.md)
- 注意: RQ-11-025とPlatform DD 2.7を継承し、Window生成時の選択固定、C ABI追加宣言、package feature set、Python配布案、case/test設計の各文書改訂は2026-11-10に利用者承認済み。承認済み文書もAPI実装・artifact収録・試験合格を意味しない。現在のprofileに複数renderer backendが実装済みとは確認されていない。Python plugin ABI/loader lifecycleは未決で、実装計画に独立の設計承認gateがある。
- 再利用できる観察: 現行wrapperはWindowを`create(runtime)`で生成し、別操作でopenする。C ABIはUTF-8 pointer/lengthとowned errorを使う。backend選択はWindow生成時のoptional設定としてCoreへcopyし、Window objectの寿命中固定する案がUI構築時選択に合う。Python通常実行はcompile-time backend pruningを要求せず、現行native loaderを維持する。PyInstallerは`--add-binary`/specの`binaries`でnative binaryを含め、`sys._MEIPASS`から絶対pathを解決できるが、現行loaderにはbundle path解決がない。shared libraryをbundleへ含めれば総配布サイズには加算されるが、Core/C ABI本体binaryのsizeとは別。backend packageの別installや外部path loadならapp bundleへ全候補を含めなくてよい。Core重複を避ける候補はshared Core/C ABI + backend別shared libraryで、Rust trait objectではなくversioned C ABI plugin tableが必要。plugin handleはRuntime/Window資源より長く保持し、終了後解放する。Python source-buildはsdistからPEP 517 build backendでplatform wheelを生成する方式を使い、setup.pyを直接実行する配布形にしない。native buildにはtoolchain/development dependencyが要る。通常利用はCI-built platform wheel、明示的source buildは別artifact identity/digestとして記録する案。full C ABI runtime variantはplugin ABIが不要だがCore重複となり、Runtime作成前に一つを選ぶ。backendをcompile/linkする境界は共通native C ABI artifactで、言語wrapperごとではない。静的link化による性能向上は測定で確認する。現行各profileで複数backendが登録済みとは確認できていない。
- Core実装観察（2026-11-10）: backend factory SPIは`ui_window.rs`、Window state生成は`lib.rs`の`create_ui_control`、peer作成は`runtime.rs::window_open`にある。Current official IDs are `windows.win32-d2d` and `linux.drm-gbm-egl-gles`; `PlatformRuntimeFactory` gains default/registry/backend-specific creation hooks so legacy factories retain their default path. Core test `window_presentation_backend_is_resolved_at_creation_and_remains_fixed` covers default/explicit/unknown/init-failure/reopen behavior. Cargo features are planned at the shared C ABI artifact boundary, not in Core or wrapper crates.
- C ABI実装観察（2026-11-10）: additive symbol `ui_abi_1_window_create_with_presentation_backend`は既存Window createと同じhandle/error/status規則を使い、UTF-8 pointer/lengthを検証して同期中だけ借用し、Coreがowned selectorへcopyする。C/C++ header probesとABI runtime smokeの双方でsymbolを参照できる。local Ninjaが未導入の環境ではVisual Studio generatorでABI consumerをビルド・実行できる。
