## 適用した方針

- 列挙対象が固定の属性・言語・機能なら、反復した見出しと定型文ではなく表で管理する。
- 独立したRQ IDを維持する各要求には、対象・満たす条件・外から確認できる結果を記載する。
- 要求の受入確認は、設計担当へ割り当てるだけで済ませず、実行時に比較・観測できる結果を示す。
- 詳細化は承認済み要求の意味を保ち、具体APIや下位実装方式を未承認の要求事項として追加しない。改訂版全体のレビュー状態を要求自体の承認と区別する。
- 要求から下流設計・testへの参照を作らず、RQ IDを安定して保つ。
