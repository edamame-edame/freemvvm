# Scope: C# Property wrappers

- `UiProperty<T>` currently supports `bool` and `long` through `TryCreate`, `TryGet`, `TrySet`, and explicit close/Dispose. Other managed types must be rejected before any native call until a matching typed mapping is implemented.
- C ABI `ui_bool` is `byte` and valid only as 0/1; `int64_t` maps directly to C# `long`. Never route either value through object-sized pointers or narrower integers.
- Every Property create/get/set call borrows the Runtime or Property token through `TokenOwner.AcquireLease`; explicit release failure leaves the owner retryable, and Dispose uses the cleanup ticket after failure.
- The real host C ABI without a UI loop bridge still supports creating and reading/writing properties on the Runtime's creating thread; only shutdown admission is unsupported in that host configuration.
- Extend the no-third-party C# console test harness with the Property fake dispatch, and keep the separate consumer process testing the actual built C ABI. `tools/dev.py check` runs Runtime and Property focused tests and consumers.
- `UNIT-WRAP-CS-PROP-BOOL-I64-001` passed local focused/consumer tests, Windows `tools/dev.py check`, Rust minimum, and GitHub Actions run 40049830264 on both Windows and Linux for implementation commit `0330ed2`.
- `UiProperty<T>` also supports `double` through direct C ABI `double` create/get/set calls. Do not convert F64 through decimal, formatting, or a wrapper-side cache; fake ABI tests use `BitConverter` to assert the raw IEEE-754 bits across the managed boundary.
- F64 equality is Core behavior: NaN values, same-sign infinities, and positive/negative zero compare equivalent; an accepted equivalent set keeps the currently stored representation. The C# consumer checks distinct NaN payload and signed-zero preservation through the real C ABI.
- `UNIT-WRAP-CS-PROP-F64-001` passed focused and consumer tests, Windows `tools/dev.py check`, Rust minimum, and GitHub Actions run 40050770415 on both Windows and Linux for implementation commit `a8f80fe`.
- `UiProperty<T>` supports `string` through strict UTF-8 C ABI create/get/set calls. C# strings with unpaired UTF-16 surrogates are rejected before native calls; invalid UTF-8 returned by the ABI is reported as `UI_INTERNAL_ERROR` without replacement. Getter buffer-too-small responses trigger reallocation and retry, and no partial buffer is decoded or exposed.
- `UNIT-WRAP-CS-PROP-UTF8-001` passed focused fake-ABI tests, the separate real C ABI consumer, Windows `tools/dev.py check`, Rust minimum, and GitHub Actions run 40052347620 on Windows and Linux for implementation commit `b6bfb3b`.
- C# `DecimalValue` stores the canonical DECIMAL `ulong` bits directly; `TryFromParts` enforces scale 0..31 and coefficient 0..2^58-1. `TryFromDecimal`/`TryToDecimal` never round: they may remove exact trailing decimal zeros only when needed to fit the counterpart scale/coefficient range. Keep Property wrapper logic free of numeric-equivalence normalization; Core retains the stored representation for numerically equivalent sets, including signed zero.
- `UNIT-WRAP-CS-PROP-DECIMAL-001` passed focused fake-ABI tests, the separate real C ABI consumer, Windows `tools/dev.py check`, Rust minimum, and GitHub Actions run 40053093079 on Windows and Linux for implementation commit `166a6a0`.
